Build a complete production-ready consumer web application called **AncestryTrip**.

Core positioning:

**Turn your family history into a journey.**

The business helps people turn ancestral locations and family-history information into personalized heritage travel itineraries.

IMPORTANT BUSINESS MODEL:

This is a self-service consumer business. No sales calls. No demos. No contacting companies. A stranger must be able to discover the website, use the free tool, pay online and receive their product without human intervention.

PRODUCT:

Create a beautiful, trustworthy, emotionally engaging website with these pages:

1. Home
2. Create Your Trip
3. How It Works
4. Example Trip
5. Pricing
6. FAQ
7. About
8. Contact
9. Privacy Policy
10. Terms
11. Customer Report page
12. Owner/Admin dashboard

CORE FREE FLOW:

The visitor enters:

* ancestral country
* ancestral region/state/province
* ancestral city/town/village if known
* optional ancestor surname
* optional ancestor first name
* optional approximate birth/death years
* current or planned destination
* trip length
* travel budget
* interests

Do NOT ask users for unnecessary sensitive information about living relatives.

Generate a free preview containing:

* a concise interpretation of the information they provided
* up to 3 relevant heritage/travel locations
* one sample day of itinerary
* historical context
* a short research checklist
* a clear explanation that the preview is not proof of genealogy
* a strong CTA to purchase the complete report

PAID PRODUCTS:

Product 1:
**Heritage Trip — $19**

Generate:

* personalized trip overview
* day-by-day itinerary
* relevant towns and heritage locations
* museums
* archives
* churches/cemeteries where genuinely relevant
* historical sites
* suggested research questions
* practical travel guidance
* source/reference section
* printable report layout

Product 2:
**Deep Heritage Trip — $49**

Include everything in the $19 report plus:

* expanded heritage research plan
* additional relevant locations
* more historical context
* suggested archival research
* suggested local-history research
* more detailed trip planning
* printable premium trip book

Do NOT make subscriptions part of the first version.

PAYMENT:

Use Stripe through Replit's Stripe integration.

Implement:

* Stripe Checkout
* one-time purchases
* webhook/payment confirmation
* order records
* successful-payment verification
* protection against duplicate fulfillment
* customer email collection
* post-payment success page
* report access after successful payment

The customer must never receive a paid report merely because the browser says payment succeeded. Verify the Stripe payment server-side.

DATABASE:

Use the built-in Replit SQL database.

Create appropriate tables for:

customers
trip_requests
orders
reports
report_items
content_pages
analytics_events
support_tickets
operator_runs
marketing_queue

Keep personally identifiable information to the minimum necessary.

CORE RULE:

The application must NEVER fabricate genealogy facts.

Specifically:

* never claim that a surname proves ancestry
* never claim that a person lived in a location unless the user supplied or a reliable source supports that fact
* never invent birth/death dates
* never invent family relationships
* never invent archives
* never invent historical events
* never present speculation as fact

Separate every report into:

1. User-provided information
2. Verified/reference information
3. Suggestions/inferences

Where factual historical information is used, provide source links when available.

Make the uncertainty visible.

DESIGN:

Create a premium travel/history brand.

The design should feel:

* elegant
* trustworthy
* emotional
* historical
* modern
* extremely simple

Avoid generic "AI startup" aesthetics.

The primary CTA should be:

**Discover Your Ancestry Journey**

The home page should immediately explain the product in one sentence.

CONVERSION:

Optimize the user journey:

Landing page
→ free trip generator
→ preview
→ pricing
→ Stripe Checkout
→ paid report
→ share/download

Do not put the paywall before showing meaningful value.

The free result should be genuinely useful.

* completed purchases

* most popular topics

Create an owner dashboard showing these metrics.

Create a protected /admin dashboard.

Display:

Add an "AI Business Briefing" section summarizing:

What happened
Why it matters
What should be changed
What the AI changed automatically
What requires owner approval

AI:

Use Gemini through a server-side environment variable called GEMINI_API_KEY.

Never expose the API key to the browser.

Use the model for:

* report generation
* summarization
* historical-context drafting
* customer support
* content ideation
* content creation
* analytics interpretation
* conversion-copy experiments

Create a reusable AI service layer rather than scattering model calls throughout the code.

ROBUSTNESS:

Add:

* loading states
* error handling
* retry handling
* rate limiting
* abuse prevention
* input validation
* server-side payment verification
* structured logging
* clear error messages
* graceful failure when AI services are unavailable

Do not allow unlimited expensive AI requests from a single visitor.

FREE PREVIEW ABUSE:

Limit anonymous free generation to a reasonable number per IP/session/day.

Do not make the paid report dependent on a long-running browser session.

REPORT DELIVERY:

After successful Stripe payment:

1. verify payment
2. create order
3. generate report
4. store report securely
5. give customer a unique report URL
6. allow printing/downloading
7. ensure the report can be regenerated or retrieved later

For the MVP, a polished print-friendly HTML report is sufficient. Do not introduce unnecessary PDF infrastructure if browser print-to-PDF provides a reliable result.

LEGAL/TRUST:

Create placeholders for:

Privacy Policy
Terms of Service
Refund Policy
Contact

Make it clear that AncestryTrip provides travel/research assistance and is not an official genealogy-record provider.

Create a visible disclaimer that AI-generated historical suggestions can contain errors and that important genealogy claims should be independently verified.

Do not collect sensitive information unnecessarily.

TECHNICAL PREFERENCE:

Use a straightforward maintainable full-stack architecture.

Prefer simple code over unnecessary frameworks.

Use the built-in Replit database.

Use environment variables/secrets for all API keys and credentials.

Create seed/sample data so the example trip works immediately.

Before considering the app complete, test:

* free generation
* invalid input
* repeated requests
* Stripe test payment
* failed payment
* successful payment
* duplicate webhook
* report generation
* report retrieval
* admin authentication
* mobile layout
* desktop layout
* SEO metadata
* robots.txt
* sitemap.xml

Do not stop at creating a landing page.

Build the actual functional business.
